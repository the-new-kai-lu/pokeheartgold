# First-badge donor state census (source-only)

Run with **owner-local** source checkouts; there is no fetch, asset extraction, ROM, save or native-game operation:

```sh
python3 scripts/census_campaign_state.py \
  --emerald /workspace/pokeemerald --platinum /workspace/pokeplatinum \
  --output /tmp/hg-campaign-first-badge-census.json
python3 -m unittest discover -s tests -p test_campaign_state_census.py
```

Optionally run donor-specific anchor tests with `CAMPAIGN_EMERALD=/local/pokeemerald CAMPAIGN_PLATINUM=/local/pokeplatinum python3 -m unittest discover -s tests -p test_campaign_state_census.py`; no donor paths are inferred for tests.

Keep the report outside the repository: it is an evidence artifact, not imported game content. The CLI requires both paths. JSON includes each donor's actual Git revision **and dirty status**, SHA-256 for semantic source inputs, scope-file SHA-256, unique saved ID references with source:line read/write evidence, separate *allocated namespace ranges*, explicit scoped map/event/script source paths, and unresolved references. `resolved_saved_reference_counts` are **not** complete campaign counts: `reference_census_complete=false` wherever cross-language/native/unknown dependencies remain. The committed scope at `scripts/campaign_scopes/first_badge.json` manually selects the opening-to-first-gym corridors and selected interiors: Emerald Littleroot → Oldale/Route 103 → Petalburg/Route 104/Petalburg Woods → Rustboro Gym; Platinum Twinleaf/Route 201/Lake Verity → Sandgem → Jubilife/Route 203 → Oreburgh Gate/Mine/Gym. Each map has its exact event JSON and script source path in the report. The Rustboro Gym and Oreburgh Gym badge scripts are the two endpoint source anchors. Selection is *not* a graph proof of every accessible map or of temporal event reachability.

The scanner reads map event flags and trainer scripts, all labels in scoped map script files and recursively follows statically named calls into donor shared script source. Emerald switch/case labels are followed conservatively (all cases, not a proof of the executed case). Platinum map init-script files are included if present. Platinum hidden-item numeric background scripts are mapped to persistent flags only in the verified `include/script_manager.h` and `src/script_manager.c` offset range using `generated/vars_flags.txt` (e.g. Oreburgh 8087→0x0331, 8257→0x03DB); other nonlocal numeric IDs remain explicit unknowns. Platinum `CallCommonScript` and direct macro aliases are followed through the verified `asm/macros/scrcmd.inc` and `scripts_common.s` numeric `ScriptEntry` table (Sandgem Pokecenter nurse 0x7D2→the Pokerus flag). Relevant dispatcher and macro sources are hashed; a changed known dispatch signature fails closed. Symbol values come from Emerald constants or Platinum generated lists, using restricted literal/name/add/subtract/modulo arithmetic, never Python evaluation of donor input. Emerald daily flags (including flower shop 0x0930) remain saved; map-local flags/vars, script-local vars and Emerald special RAM flags are excluded from saved counts. Trainer opponents are counted as their donor trainer-defeat flag IDs, not as a separate additional save allocation. The namespace range labels are context **only**: named, reserved or unused IDs do not prove required state, nor free HGSS capacity.

These are **stored-ID references**, not proof that every counted flag needs durable cross-map storage. Emerald `FLAG_NURSE_UNION_ROOM_REMINDER` (`0x0880`) is physically in the saved-flag array but is cleared during map loading by `src/event_data.c` (the lifetime-evidence source is included in the report hashes). It remains in the physical saved-reference count; neither that count nor a flag's symbolic name establishes its lifetime.

`reachability_proven=false` and `allocation_approved=false` are deliberate. The map-scoped union can **overcount** post-badge branches, shared scripts and inaccessible interactions. It can **undercount** unresolved dynamic IDs, calls, C specials, native callbacks, scripts outside selected maps, non-flag/var world state and cross-bank dependencies. Unknown records are review work, not zero-cost state. Read/write evidence classifies syntax/operands, not control-flow or full engine-side mutations (especially automatic trainer-defeat updates). Sources are not preprocessed for conditional builds. No whole-campaign, per-badge temporal, save-size, journal/crash-safety, or HGSS allocation assertion follows from this report. The prior capacity audit found **zero** proved additional capacity; native 0x416e/0x416f were opening-only. In particular, HGSS flags `0xB50–0xB5F` are inside the host's daily-clear interval (`0xAA0` plus 192 flags), not proved durable spare storage. Full Emerald/Platinum campaigns and unchanged native HGSS save compatibility remain unsolved.
